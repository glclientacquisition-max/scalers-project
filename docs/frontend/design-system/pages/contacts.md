# Contacts

**Route:** `/contacts`  
**Job:** Named callers. Not a CRM.

**Chrome:** Large in-page Contacts title (`deskListTitleClass`). No product wordmark. Search field (`ContactsSearch`, `type="search"`, Name or number) and one primary **Add** sit on the lead row at every width. Add opens DeskDialog options: New (manual `AddContactPanel` form) · CSV (`/contacts/import`) · From this phone (`PhonebookImportButton` / Contact Picker, hidden when the picker is unavailable). No standalone Import CSV or phonebook CTAs on the lead. One filter row (`InboxFilterPills`, `contactFilterPills`, `aria-label` Filter contacts): All · Recents · Favourites · Saved · Unsaved. Recents and Favourites are filters on that row, not a second strip. Unsaved appears once. Same chip DESIGN as Inbox purpose (`deskRateCardClass`, solid active `#005CCC`, muted idle, `min-h-11`, snap scroll, trailing fade). Counts only when already loaded (Recents, Favourites, Unsaved). Not `DESK_LINKS`. Purpose piles (Needs you / Visits / Holds / …) stay Inbox-only. Sort is a labeled `ContactSortSelect` (`aria-label` Sort contacts): Last call · Name. Nested contact files and import do not render Contacts as a page title.

**One family:** Phone (`< md`) is the list row. `md+` is one table. `lg+` is the same table with a Phone column. No third card layout. Hits stay `min-h-11` / `deskHitClass` (`h-12 w-12`). Phone `main` already clears `--desk-tabbar-clearance` (tab bar plus safe area).

**Segments:** All · Recents · Favourites · Saved · Unsaved. One pill row. Not underline FilterTabs. Not a second pile strip. Recents is `saved=recent`. Favourites is `saved=favourite`. Not bottom-nav items. No nested DeskBack for those piles. No Invite Friends. No slider skin. No Inbox purpose nouns.

**Row:** Same recipe as Inbox. Avatar, identity plus one factual subline (`contactListTitle` / `contactListSubline`: Unsaved, phone, or last call; unnamed rows put the phone first and **Unknown caller** muted under it). **+ Add name** on those rows uses `ContactNameForm` `updateContactName`. Last call time sits with the timestamp, never "last seen" or "active now". Tap the row to open `/contacts/[id]` with the list segment on the URL (`from=contacts`). No Open column. Phone column from `lg`. If a phone exists, Call + WhatsApp sit in the trailing `deskHitClass` dock (`CallLink` `tel:` + `WhatsAppLink` `wa.me`, opened only). No `callId`. No `lead_status` write-back. No delivered claims. No Online, last seen, presence dots, or live badges. Hangup Want and the four-block summary live on the person file and the call. No Calls column until a cheap per-row aggregate exists.

**Ticket strip:** `/calls/[id]` header uses `ContactStrip` in this same family (avatar, one fact). Identity only. Call + WhatsApp live once on the ticket action dock. Allowed facts: Unsaved, phone, last call. No `lead_status` or Needs you invent. No Meta theater. List Phase 1 chrome stays on `/contacts`. Do not restyle the list to match the ticket, or the ticket to invent a second row language.

**Detail:** `/contacts/[id]`. Named file: display name plus a pencil that reveals `ContactNameForm` / `updateContactName`. Unnamed file: compact **Name this caller** plus a docked Name field and Save (one row). No wrapping display title over an empty stacked field. Large identity circle in the lead. Phone stays locked. Phone, last-call fact if known (`contactLastCallFact`, never last seen). **Add to Favourites** is a text control when idle and a filled pill when active. **Inbox threads** is a text link. Honest KPI strip (`ContactKpiStrip`) under the name: Interactions and Visits done are links onto History chips. **Interactions** = assembled ticket/call rows for that contact. **Visits done** = jobs with status `done`. **Customer since** = relative months from earliest first-seen / first call / `created_at`. Hide when unknown or the count is 0 (`0 mo` does not paint). No wallpaper numbers. No glass. Notes is a collapsed accordion. History right. Phone is the list row. `md+` is the table. No `min-w-[560px]` floor. History rows are Inbox tickets for this contact (`assembleInboxItems` + `itemSignalLabel`). Stamps use `InboxPurposeChip`. Consecutive same-purpose rows inside 15 minutes group at display time. History shows 12 rows, then **View more**. No inner History scroll. Invent no Call / Request CRM types. Tap a History row that has a call (`inboxRecordHref`) to open the conversation. No Call column. If a phone exists, Call + WhatsApp sit as top `deskHitClass` icons in the header (`ContactActionDock`: `CallLink` `tel:` + `WhatsAppLink` `wa.me`). No labeled Call / WhatsApp pills under the name. Bare-profile WhatsApp is `wa.me` only. No `callId`, no `lead_status` write-back. After Save the file is Saved and the route stays. If a phone exists, **Inbox threads** opens Inbox with existing search (`inboxThreadsFromContactHref`: `purpose=all` and `q` = phone). No phone: no Inbox threads control. History What is one truncated line (`deskPreviewClass`); tap the cell to expand detail. Phone and tablet below `md` hide the bottom tab bar (`data-desk-nested`; `--desk-tabbar-h: 0`). The `md+` rail stays and shows icon plus label. `DeskBack` sits in `DeskRecordLead` with the name and Call/WhatsApp. Never a solo back row. `aria-label` is Contacts, or Call when opened from a conversation, or Inbox from a pile. Import uses the same lead row. Back from the list restores `/contacts` with `saved`, `sort`, `q`, and `page` preserved (segment preserved). Tap identity on a ticket `ContactStrip` opens this file. Import (`/contacts/import`) uses the same nested hide. The Contacts list keeps tabs.

**Do not:** ship a contact activity strip on the list. Invent Online, last seen, presence dots, or active now. Add Invite Friends. Write `lead_status` from the list. Claim delivered from a list tap. Put Inbox purpose nouns on Contacts chips. Ship VIP / Lead / Cold / SEGMENT. Fake KPI counts.

Identity is tenant + E.164 phone. The fifth call from the same number is the same contact. Last call on the list is the newest call or work stamp. Last want on the person file is the four-block summary when it is richer than History's top row.
